# Inherited objects and labels

Provenance for anything copied from a colleague's directory. **Write
the entry the day you copy the file**, not later — the details you need
are the ones you forget first.

## Why this file exists

Three failure modes it prevents:

1. **BPCells absolute paths.** A BPCells-backed `.rds` is a thin object
   holding an absolute path to an on-disk counts directory. Copy the
   `.rds` alone and it loads fine, then fails the moment you touch the
   matrix. Copy both and the pointer still refers to the original
   location. If that directory is reorganized or purged, your object
   breaks silently. Record the original path.

2. **Retroactive invalidation.** An upstream annotation or filtering fix
   invalidates every downstream result built on the old version — as
   happened in the colleague's tree when a B-cell filter change
   invalidated a whole results subtree. If you inherit labels, you
   inherit that risk; record which version you took and when.

3. **Parameter values encoded only in filenames.** `res0p3`, `from3b`,
   `_v2`, `Round2`, `preCCregress`. The filename cannot tell you which
   is current. Ask, and write the answer down.

## Before you copy anything

```bash
# copy the .rds AND its _counts/ directory together
rsync -av /nfs/<colleague>/objects/ASSET_X.rds          $BIG/data/inherited/
rsync -av /nfs/<colleague>/objects/ASSET_X_counts/      $BIG/data/inherited/

# then, in R
source("config/paths.R"); source("R/io.R")
obj <- load_object(file.path(INHERIT, "ASSET_X.rds"))   # reports BPCells paths
obj <- repoint_bpcells(obj, file.path(INHERIT, "ASSET_X_counts"))
```

**Prefer inheriting label tables over objects.** A CSV of
`barcode, lineage, celltype, subtype, label_version, source_script` is
worth more than an `.rds`: it survives freeze02, survives her continued
iteration, and does not tie your analysis to her object's internal
state. Request one object for orientation only, and treat it as
read-only reference rather than as your analysis substrate.
